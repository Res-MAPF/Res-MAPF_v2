# src/domain/solver

This is where the actual resilient multi-agent path-finding algorithm lives — the heart of the project. `solver_manager.py` is the single dispatch entry point; `resplan_solver.py` implements ResPlaN, the resilience-search algorithm that decides which joint plan survives which tolerated failures; `computeplan.py` implements the nominal (non-resilient) joint planner — Conflict-Based Search over per-agent Safe-Interval Path Planning with Soft constraints (SIPPS) — that ResPlaN calls whenever it needs a concrete plan for a given state; `Solution.py` is the plain container the whole search result is returned in. The performance work that distinguishes v2 from the Baseline (see the top-level README's Version Description) is concentrated in this folder, mainly in `computeplan.py`.

## Files

| Module | Description |
|--------|-------------|
| `solver_manager.py` | `solve_mapf()` — the one function every caller (GUI, both CLI runners) invokes to solve an instance |
| `resplan_solver.py` | The ResPlaN resilience-search algorithm: failure branching, resilience checks, plan extraction |
| `computeplan.py` | The nominal joint planner used at each search node: CBS (high level) + SIPPS (low level) |
| `Solution.py` | `Solution` — the return-value container for a solve |

### `solver_manager.py`
`solve_mapf(mapf_instance, robustness_params, search_params, stop_event=None)` is the single entry point used everywhere else in the codebase. It dispatches on the module-level `SOLVER_ALGORITHM` constant (currently only `"resplan"` is implemented, routing to `resplan_solver.resplan_mapf`); any other value raises `ValueError`. This indirection is the place to add or switch a solving algorithm without touching every call site.

### `resplan_solver.py`
Implements ResPlaN, the search that finds a joint plan resilient to up to `k` failures under the `m`/`h` budget. `Node` encodes one search state: the joint agent positions (`state`), remaining failure budget (`k`), the set of actions already known to be forbidden per agent (`failed_actions`), and each agent's failure count so far (`failure_agents`); `get_failable_agents(m, h)` returns which agents may still be made to fail from this node without violating `m`/`h`. `resplan_mapf()` is the main loop: it pops nodes from an open list, checks for goal states and duplicate/colliding states, calls `rcheck()` to see whether a node is already provably resilient via previously-verified successor states, and otherwise calls `compute_plan_cbs()` (from `computeplan.py`) to get a nominal plan for that state. For every macro-action step in that plan it branches into a "what if this action fails" child node for each failable agent and each selected failure type, using `compute_affected_actions()` to work out exactly which other actions become forbidden by that failure, and reuses unaffected agents' path suffixes (`agent_paths`) to avoid re-planning agents whose paths aren't invalidated by the failure. Resilient/non-resilient states accumulate in `R_up`/`R_down`; `predecessors` and `resilient_node_macroactions` record enough information to reconstruct the final plan, which `extract_solution_from_predecessors()` does by walking forward from the initial node once the search terminates. `compute_affected_actions()` implements the four failure semantics selectable in the UI — `topw` (topological weak: blocks the action for every agent), `tops` (topological strong: blocks all moves into/out of the destination cell for every agent, unless the destination is a goal), `individual` (blocks the action only for the failing agent), and `high-level` (blocks that same move direction everywhere on the map, only for the failing agent). `agents_can_reach_goals()` is a cheap per-agent BFS reachability pre-check used to prune a failure branch before paying for a full CBS call. This is the file to change to alter how failures are branched, pruned, or verified resilient.

### `computeplan.py`
The nominal (non-resilient) joint planner invoked by ResPlaN at each search node. `compute_plan_cbs()` runs Conflict-Based Search: `CBSNode` holds a set of constraints and the per-agent paths computed under them (`compute_low_level_solution()`, which can selectively replan just one agent and reuse the rest — used when ResPlaN only needs one agent's path recomputed after a failure), conflicts between agents' paths are found by `detect_conflict()` (vertex conflicts, edge swaps, and diagonal "crossing" conflicts where two agents pass through the same 2x2 square from opposite corners), and CBS nodes whose resulting joint-state sequence passes through an already-known non-resilient state (`states_down`) are also branched on, not just genuine conflicts. The low level, `low_level_search_cbs()`, is SIPPS: `SIPPSNode` tracks a safe-interval-bounded search node with both hard and soft constraint conflict counts, ordered lexicographically by (conflicts, f-value, real geometric cost) — the last term, computed by `move_real_cost()`, exists purely to break ties in favor of geometrically shorter routes since every move costs one timestep in the g/f accounting regardless of whether it's diagonal or cardinal. `SafeIntervalCache` is a performance optimization: it incrementally recomputes only the safe-interval table entries whose hard/soft constraints actually changed since the last call, instead of rebuilding the whole table from scratch on every CBS node — this and the `first_allowed()` binary-search constraint lookup are the main places implementing v2's performance work relative to the Baseline. `build_solution()`/`extract_pi_from_tau()` turn a CBS node's per-agent paths into the joint-state sequence and macro-action sequence ResPlaN operates on; `heuristic()` precomputes a Dijkstra distance-to-goal map per agent, reused across the whole search. Change this file to affect the underlying nominal MAPF search itself: conflict types, tie-breaking, or SIPPS/CBS internals.

### `Solution.py`
`Solution(tau_states, R_up, R_down, predecessors, resilient_node_macroactions, cost=None, cbs_cost=None)` is the plain container `solve_mapf()` returns and every consumer (GUI, both CLI runners, `sperimental_analysis.build_solutions_csv`) reads from. `tau_states` is the resilient macro-action plan (`None` if none was found); `resilient_cost` and `cbs_cost` hold the resilient plan's cost and the unconstrained ("0-resilient") CBS baseline cost respectively, used elsewhere to compute the resilience overhead ("delta %").
